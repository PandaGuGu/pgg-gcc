## 1. 目标与验收

| 项 | 定义 |
|----|------|
| 输入 | 单参数表达式字符串（词法集：十进制数字、`+ - * / ( )`、一元负号；空白跳过的 ASCII 空白） |
| 输出 | 标准输出：一段 i386 AT&T 汇编（`.s`），其运行结果 = 表达式十进制值（无 libc，自带 `_start` + `write` + `exit`） |
| 自证 | `tests/run.sh` 既有 10 用例全 PASS；期望值**手算**，与任何编译器无关 |
| 红线 | 不调用任何 C/C++ 编译器；不读取任何编译器源码；阶段门控对照关闭 |
| 限制声明 | 字面量与中间结果限定 int32 域（`≤ 2^31-1`），溢出为未定义行为（v0 不做运行时检查，登记限制即可） |

## 2. 关键权衡（Trade-offs，非结论）

### T1 语法结构：最小树（节点池）vs 直接发码
- 选项 A（推荐）：**节点池数组**——`kind/ival/left/right` 四个 32 位槽，固定容量（如 512 节点），
  index 即指针，自回环检查防溢出。**汇编写递归下降 = "过程 + 栈帧"，天然可用**；AST 先建后发码，
  使一元负/优先级/括号不用在发码时改弦更张。
- 选项 B：token 流直接栈式发码。更省，但在括号/一元负组合下需层层特判，v1 加变量时重构面大。
- 结论：**选 A（最小树）**。理由：后续每阶段的扩展面最小（v1 只加 kind 与符号表），
  遵循"管线四段：词法→语法→代码生成→汇编文本"的基线约定；节点池容量线性、无动态内存。

### T2 无 libc 的 I/O 代价
- 输入：`_start` 从栈取 `argc/argv`，游标寄存器遍历 `argv[1]`。
- 输出：`.s` 文本与十进制数字均用裸 `write` syscall 产出；**行缓冲**（先组装一行再一次性 `write`），
  控制 syscall 次数与代码复杂度。
- 诊断：v0 只做**最小单行错误文本**（如 `error: <pos> <token>`）+ 非 0 退出码；
  不追求 2.95 风格诊断——diff 对齐明确**延后**到对照放行阶段。

### T3 生成程序的运行形态（无 crt/libc）
- 生成代码 = 固定 **prologue**（`_start` 模板）+ 表达式求值（栈式 `pushl/popl`，结果入 `%eax`）+
  固定 **epilogue**（`print_decimal` + 换行 + `exit` syscall，作为常量文本内嵌输出）。
- 权衡：同一 epilogue 每次重复输出 vs 外链公共运行时文件——v0 选**内嵌模板**（自足、单文件可审计）；
  Rule of Three：待出现第 3 个需要公共运行时的版本再抽公共运行时库。

### T4 语义锚点：除法截断
- C89 语义：整数除法商**截断向零**（`-7/2 = -3`）；i386 `idivl` 商天然向零截断 → **零额外代码即一致**。
- 取模与负余数语义不在 v0 词法内（无 `%`），留到对应阶段，作为"理解偏差项"候选登记。

### T5 工具边界（as/ld 是否为"蛋"）
- as/ld = 助记符↔二进制 的机械翻译器，**不提供任何编译语义**；属项目地板层既定工具
  （2026-08-24 起自证管线即用它），不构成被禁的"蛋"。
- 全部"编译语义"（词法/语法/发码）一律在 `pggcc0.s` 内自己实现——这正是无蛋的意义。

## 3. 模块划分（单文件、过程分层）

| 层 | 职责 |
|----|------|
| util | 十进制→文本（`print_decimal`）、`write` 行输出、数字解析（`atoi` 精简版，含越界钳制） |
| 词法 | 从 `argv[1]` 取 token（`kind: NUM / LP / RP / OP / END` + `ival`），空白跳过 |
| 语法/发码 | 递归下降 `expr → term → factor`；factor = 数字（发 `pushl $n`）/ `( expr )` / `- factor`；  优先级由层级天然保证；每步追加指令到行缓冲 |
| 模板 | prologue/epilogue 常量文本输出 |

**寄存器约定**（实现时以单页注释固化在 `pggcc0.s` 头部）：`%esi` 输入游标、`%eax` 临时值、
`%ebp/%esp` 为编译器自身过程栈；数据段常量放 `.rodata`。

## 4. 里程碑（顺序推进，每步可验收）

- **M1 骨架**：可运行的裸二进制——`_start` + 输出固定文本 + `exit`（打通裸 syscall 链）
- **M2 发码**：词法 + 递归下降 + 指令文本生成；手工地 `as`/`ld`/运行 3 个冒烟用例
- **M3 自证**：`tests/run.sh` 10/10（手算期望值）
- **M4 收尾**：ORIGIN 登记 v0 行（ISO/IEC 9899:1990 §6.3 表达式；整数字面量另注 §6.1 词法）；日志留痕；README 构建节已切换无蛋命令

## 5. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 汇编可读性/调试成本高 | 教学级注释密度；过程边界清晰；寄存器约定单页文档化；M1/M2 先小步验收再 M3 |
| 溢出/字面量越界 | v0 明确限定 int32 域并登记为限制；不做运行时检查 |
| v1 变量/栈帧扩展 | T1 节点池 + 递归下降天然可扩展（加 kind、符号表与局部槽位） |
| 与真实 GCC 2.95 的行为 diff | 留到用户放行对照阶段（基线 §4.2 流程），此处不比对 |

## 6. 验收门（v0 完成的定义）

1. `tests/run.sh`：构建与 10 用例全 PASS，构建链全程无 C/C++ 编译器参与；
2. 输出 `.s` 人工抽检可读、逻辑自洽（栈式求值、截断除法正确）；
3. ORIGIN v0 行更新（标准条款 + 实现日期）；docs/logs 当日条目齐全；
4. 未越红线（无编译器对照、无源码阅读）。

## 7. 接口定标（2026-08-25，评审收尾；实现时可推翻并留痕）

| 项 | 定标 | 理由 / 备注 |
|----|------|-------------|
| 空白字符集 | 跳过 4 类 ASCII 空白：空格（`0x20`）、`\t`、`\n`、`\r` | 覆盖 C 词法空白主体与命令行传参场景；v0 输入为单行，`\n`/`\r` 防御性跳过 |
| 语法错误文本 | `error: <位置> <token>`；位置为字节偏移（0 起），token 单字符（数字串截断 8 字符） | 最小单行诊断，满足自证与人工排查；2.95 风格 diff 对齐留待对照放行阶段 |
| 退出码 | 0 = 编译成功；2 = 语法错误；1 = 无参数/多余参数/非法输入 | 三态区分；tests/run.sh 以非 0 判定失败 |
| `.s` 输出通道 | 汇编 → stdout；错误 → stderr | 与 tests/run.sh 捕获方式一致，错误与产物分离 |
| 数字域 | 字面量与中间结果限定 int32（`≤ 2^31-1`）；解析越界钳制、不报错 | 与 §1 限制声明一致；v0 不做运行时检查 |
