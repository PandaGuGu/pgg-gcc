## 1. 目标与现状

### 1.1 "移植性"在本项目指什么

本项目是"无蛋自举"编译器（boot0 用 pggcc 语言书写并编译自身）。对这类项目，"平台移植性"有两个
层面，必须先分开：

- **源码层移植**：`src/boot0.pgc` 是标准 C90 子集文本，**理论上已可移植**——抄源码到任何机器即可重编。
- **二进制/自举层移植**：要在**新目标平台（新 ISA / 新 OS）上让编译器原生跑起来并自举闭台**。
  这才是本文件要解决的问题。

### 1.2 现状：声明 vs 实际绑定

README 接口处标注"平台：Windows / Linux / macOS"，属**开发宿主**策略；实际**运行目标**是
**x86（i386）Linux ELF 单平台**。把编译器钉死在单平台的，是三层机器码绑定：

| 层 | 现状 | 绑定原因 |
|----|------|----------|
| 发码层 | 只产 i386 AT&T 汇编 | 代码生成器只识别 x86 寄存器/寻址/调用约定（cdecl） |
| 引导层 | 新平台起点须先有可执行入口（手写 stage [pggcc4.s](file:///c:/Users/Administrator/Desktop/pgg-gcc/src/pggcc4.s)） | 当前"第一入口"只有 x86 一处 |
| 运行层 | `_start` + 裸 syscall（read/write/exit） | 只认 Linux x86 的 syscall 号与入口约定 |

### 1.3 已经可移植的部分

- 编译器本体源码（boot0.pgc）——ISO C90 子集，换平台无需改动语法层/语义层。
- 顶层管线（词法→语法→发码）与硬件/OS 无关；只有最后的**指令选择与运行时序列**是绑定的。
- 开发宿主跨 OS：Windows（WSL）/ Linux 原生均可构建，与目标无关。

## 2. 移植的本质：新平台的"第一个编译器入口"

在任何新平台上让自举编译器原生运行，都必须回答同一个问题：**在新 ISA/OS 上，第一段能跑的程序
从哪来？** 经典 T 图闭台表述如下（以新 ISA = ARM64 为例）：

```
开发机 (x86)                           目标机 (ARM64)
bin0 ──编译 boot0.pgc──▶ arm64.s ──arm64-as/ld──▶ bin1_arm64 (原生可执行)
                                                   └─编译 boot0.pgc─▶ arm64 汇编 ─▶ bin2_arm64
                                                                    （bin1==bin2 固定点 ⇒ 自举闭台）
```

区别只在于"交叉编译这一步怎么做、由什么工具完成"。候选路线的差异正在于此：

## 3. 候选路线

### 路线 A：多后端 + 交叉自举（全程无蛋）—— **推荐**

编译器本体（boot0.pgc）新增**第二代码生成后端**（用 pggcc 语言书写，随本体自举），开发机上既有
bin0（x86）直接产出目标 ISA 汇编，用目标平台的 binutils 汇编/链接，得到目标平台的原生编译器，
再在目标平台（或模拟器）上走完整闭台验证。始终保持"零 C/C++ 编译器参与"红线。

**A-1 AMD64 后端（推荐起点）**：
- 全链路闭环可在本机完成：WSL Ubuntu 本身就是 x86-64，交叉产出的 AMD64 二进制**原生可直接运行**
  验证，**零新增环境依赖**（不需要模拟器）。
- 变更面最小：同 AT&T 语法、同 GAS/ELF 世界观（仅 64 位化 + SysV ABI + `syscall` 指令代替
  `int 0x80`）。改动集中在寄存器宽度、寻址、调用约定、syscall 号四处。
- 顺带收益：内存/地址从 int32 域升到 int64 域，缓解引擎上限族（MAX_*）压力。

**A-2 ARM64 后端（次选，依赖 Q2/Q4 放行）**：
- 需跨 binutils（`aarch64-linux-gnu-as`/`-ld`）；跨 binutils 与现用 as/ld 同为"助记符→二进制"
  机械翻译器，定位上不新增编译器，但属**基线变更，须用户放行**（Q2）。
- 闭台运行验证需模拟器（如 `qemu-user` + binfmt）扮演"CPU/硬件"角色——同样须用户放行（Q4）。
- 变更面大于 A-1：新指令集世界观（条件码/加载-存储/重定位），是检验"发码层是否真正解耦"的硬测试。

**A-3 发码层抽象方式（决策点 D1，已定：D1b）**：
现有发码层与 i386 指令选择耦合（单遍、栈式求值）。两种做法权衡如下（草案期曾推荐 D1a，
**2026-08-26 用户改选 D1b**）：
- (D1a) **发射层参数化**：保留单遍结构，把"指令选择+寄存器模型"收敛为带目标参数的发射函数群
  （宏/分发）。改动集中在发射层，造价低；两个后端共享同一高密度单遍解析，耦合仍存在但可管理。
- (D1b) **引入轻量 IR（已选）**：解析产出指令式中间表示，后端按目标消费。解耦最彻底、后续加 C99/C++
  受益，代价是对单遍结构的一次大重构——落地按 §5 P1 门控分阶段进行，每步 x86 行为零变化。
- 否决考量记录：Rule of Three 视角 D1a 更轻，用户以"后端解耦最大化 + 后续特性面受益"为由推翻推荐。

### 路线 B：自研字节码 VM（把移植面集中到一个点）

- 编译器输出改为**自研栈式字节码**，解释器也用 pggcc 语言书写（随本体自举）。
- 收益：编译器本体彻底与 ISA 无关；移植面收窄到"每次写一个解释器"，比写整个后端小。
- 代价：解释器本身在新 ISA 上仍需一次原生引导（回到 §2 的同一问题），且运行性能降低、闭台验证
  成本不变。适合未来想落到微控制器/自研硬件的场景；对"跑通用 OS"的目标属过度设计。

### 路线 C：放宽红线（最快，但改变项目性质）

- **C-1 极小 C 引导垫**：用目标平台自带 C 编译器编一个几十行的自研 VM/引导器作为机械入口，
  一举免除全部后端与跨 binutils 工作。熵最低，但**编译器本体的构建链不再纯 pggcc/AI 汇编**，
  与"彻底无蛋"决策（baseline §6）冲突，须用户明确放行并重定义红线。
- **C-2 WASM 目标**：输出 WASM，天然全家桶移植（浏览器/各运行时）。但引入外部运行时依赖，
  脱离 as/ld 链，且与本项目"自研到汇编地板"的定位相悖。

### 对照表

| 路线 | 无蛋红线 | 新增依赖 | 每次新 ISA 成本 | 适合目标 |
|------|:---:|----------|------------------|----------|
| A-1 AMD64 | ✅ 保持 | 无（本机原生可验证） | 一个后端（同世界观，最小） | 通用 OS（Linux 系） |
| A-2 ARM64 | ✅ 保持 | 跨 binutils（Q2）、qemu（Q4） | 一个后端（世界观不同） | 移动/嵌入式 Linux |
| B 字节码 VM | ✅ 保持 | 无 | 一个解释器 + 字节码格式设计 | 微控制器/自研硬件 |
| C-1 引导垫 | ❌ 冲突 | 目标平台 C 编译器 | 一个几十行垫层 | 尽快落地、不计红线 |
| C-2 WASM | ⚠️ 变形 | WASM 运行时 | 一个后端 | 浏览器/通用运行时 |

## 4. OS 轴（与 ISA 轴正交）

目标若是 Linux 之外的 OS，仍可沿用"后端不变 + 运行时适配表"：每 OS 一份**入口约定与 syscall
号/参数表**（取自公开 ABI 文档），发码层只出"通用运行时调用"，由适配表落到具体 OS。此为大后端之外的
独立小成本项，建议列为本路线图最后一个里程碑（O1）。

### 5.1 P1 实施规范（轻量 IR v0.1 —— 值流化输出缓冲，D1b 第一步）

> **定位**：D1b 决策「引入轻量 IR」的最小可行落地。不追求完整指令集 IR，先打通
> 「解析 → IR 缓冲 → 后端渲染」三段链路，为 P2（AMD64 后端）提供可替换的渲染层。
>
> **核心设计**（2026-08-26 起草）：
> 1. **IR 缓冲**：boot0 新增全局 `irt[65536]`（记录类型：0=字符串地址 / 1=整数）/ `irv[65536]`
>   （记录值：字符串地址或整数）/ `irc`（当前条数）。容量按自编译 .s ≈ 600KB 估算条数级需求。
> 2. **替换内建调用点**：boot0 源码内全部 `print_str(...)` → `ostr(...)`、`print_int(...)` → `oint(...)`
>   （print_err/print_decimal/print_char/exit 保留直出——错误/运行时路径不经过 IR）；
>   `ostr`/`oint` 仅追加 IR 记录，不再即时输出。模板运行时（eh() 的 `_start`/print_str 等
>   目标程序文本）同样走 ostr——它是目标程序的文本，非 boot0 运行时行为。
> 3. **后端渲染器**：`irgo()` 在 main 尾部（eh() 后）统一消费 IR：类型 0 → `print_str(地址)`、
>   类型 1 → `print_int(值)`，输出顺序与原 print 序列逐字节一致。
> 4. **行为门控**：i386 产出 .s 必须与改造前**逐字节一致**（run_boot 232 用例的编译产物 +
>   boot_b4 门1/门2 固定点），此后再做 AMD64 渲染器。
>
> **分步实施**（P1-a 值流化 → P1-b 指令语义化）：
> - **P1-a**：输出去向改为 IR（本规范全量落地）→ 验收：三线回归全绿、固定点不破、.s 抽样比对一致。
> - **P1-b**：将 IR 从「值流」升级为「指令流」——识别高频发码模式（pushl/leal/movl/二元运算/跳转/
>   符号引用），编码为操作码+操作数，渲染器按操作码分发（为 AMD64 后端提供指令级选择点）。
> - **P2**：新增 AMD64 渲染器（同一 IR 流按 64 位语义输出）+ SysV ABI + 64 位 syscall 运行时。
>
> **风险**：IR 缓冲容量（E10 预期：IRC 上限族）；ostr 参数为地址、渲染时生命周期（boot0 进程内
>  .rodata/sts 地址全程有效，仅编译期使用）；wpf() 自用函数（ostr/oint 双段拼接）需保持调用点
>  语义等价。
>
> **P1-a 完成（2026-08-26）**：值流化输出缓冲已落地并自举链验证——
> - boot0 新增全局 `irc/irt[131072]/irv[131072]` + `ostr()/oint()`（追加 IR 记录，不再即时输出）+
>   `irgo()` 后端渲染器；全部发码调用点 `print_str/print_int` → `ostr/oint`（print_err 保留直出）。
> - **发现面缺口并登记**：boot0 自举链无 `(type)expr` 强转语法（`(int)s`/`(char*)irv[i]` 编译报错
>   `error: <pos> int`，pggcc4 支持而 boot0 不认）；以弱类型直接赋值/传参回避。
> - **门控验证**：run_boot **232/232**、boot_b4 闭台**全门 PASS**（门1 boot0b.s==boot0c.s 643214B
>   逐字节、门2 bin1==bin2、门4 24/24、门5 3/3）、run.sh **72/72**——P1-a 闭环。
> - 下一步 **P1-b**：IR 指令语义化（高频发码模式编码为操作码+操作数，渲染器按操作码分发）。
>
> **P1-b 首轮完成（2026-08-26）**：IR 记录类型扩展（0=文本/1=整数/2=操作码，操作码后随参数记录）；
> 新增 `OP_PUSHI/OP_PUSHL/OP_STORE/OP_JZ/OP_JNZ/OP_JMP/OP_LBL` 七操作码 + `irop(op,a)`；
> `em_p/em_ld/es_/em_jz/em_jnz/em_jmp/em_lbl` 七个结构化单参发码函数改为写操作码，`irgo()`
> 按操作码分发（pushl imm/offset、movl 存储、jz/jnz/jmp/label）——AMD64 渲染器可在这些
> 分发点按 64 位语义重写。`em_o/em_cm` 等复杂多行文本模板保留值流透传（P1-b 续轮迁移）。
> 门控：run_boot **232/232**、boot_b4 闭台全门 PASS（固定点不变）、run.sh **72/72**。
>
> **P1-b 续轮完成（2026-08-26）**：`em_o`（15 种一元/二元/逻辑运算符）与 `em_cm`（6 种比较）
> 也语义化为 `OP_BINOP`/`OP_CMP` 操作码（参数=operator token），`irgo()` 渲染器内按 token
> 分发展码文本。至此发码层全部运算/跳转/存储/压栈/标签指令均为操作码+参数；仅复杂寻址
> （多维数组/struct 链取址）、数据段（.data/.rodata/.bss）、运行时模板文本保留值流透传。
> 门控：run_boot **232/232**、boot_b4 闭台全门 PASS（固定点不变）、run.sh **72/72**——P1 完成
> （轻量 IR 指令语义化，i386 行为零变化）。下一步 **P2：AMD64 渲染器 + SysV ABI + 64 位 syscall
> 运行时**（同一 IR 流按 64 位语义输出）。

### 5.2 P2 实施规范（AMD64 后端 —— 目标选择、值流文本策略、64 位运行时）

> **定位**：P2 在 32 位基线不动的前提下新增 **x86-64 代码生成**。当前发码层 = 操作码（OP_* 九类已
> 语义化）＋值流透传（复杂寻址/数据段/运行时模板仍为 i386 文本）。P2 与 P1 的**战略差异**：
> P1 只移动了"指令选择点"，P2 要把**同一 IR 流按 64 位语义完整输出**——透传的 i386 文本必须
> 逐条 AMD64 化，这是 P2 的核心工作量。

**P2-a 最小可行冒烟（目标：本机 AMD64 闭台前验证渲染通路）**：
1. **目标标记**：boot0 增全局 `int g_am;`（0=i386 / 1=amd64）。选择机制（供 P3 双目标闭台复用）：
   编译命令经 argv 传入——boot0 现仅 stdin 读程序，P2-a 起 `_start` 模板读 `argv[1]`（"i386"/"amd64"
   或省略默认 i386），置 `g_am` 后进入编译主流程（v1 曾支持"首参数=文件路径"，机制可复用）。
2. **操作码渲染 64 位化**：irgo 按 `g_am` 对 OP_* 输出 64 位版本——PUSHI/PUSHL 用 `pushq`、偏移基址
   `%rbp`；STORE 用 `movq`；BINOP 二元翻译表（addq/subl/…/cqto+idivq、`%cl` 移位）；CMP 用 `cmpq`+`setCC`
   （char 比较注意零扩展差异登记）；跳转/标签不变。
3. **值流透传文本 AMD64 化**：e_expr/p_a/pd/pgv 等内联文本（数组寻址 `off(%ebp,%ecx,4)`、leal、movzbl、
   struct 链、数据段 `.long`→`.quad`/`.byte` 等）按 g_am 分支输出——逐处登记 i386 句柄，AMD64 分支
   镜像重写（P2-a 先覆盖 run_boot 代表性用例路径所及的句柄，其余登记"待镜像"）。
4. **64 位运行时模板**：eh() 增 g_am 分支——`_start` 用 `syscall`（号：read=0/write=1/exit=60）、
   参数寄存器 %rdi/%rsi/%rdx；print_decimal/print_char/print_str/print_err/print_int 全部 64 位化
   （leaq `%rsi`、movzbq 等）；`.bss` runt_buf 不变。
5. **验收门**：`bin0 < 冒烟程序` 直出 amd64.s → `as --64` → `ld`（默认 64 位）→ 本机运行冒烟
   （如 `return 42`→42、递归 fact、print_int/print_str 几例）；x86 链三线回归全绿不受影响。

**P2-b 双目标闭台前全面化**：把 P2-a 未镜像的透传句柄按 P1-b 同构方式语义化为新操作码
（OP_LEA/OP_LDIDX/OP_STIDX/OP_MOVGB/OP_MOVLB…），使 IR 覆盖全部发码 → AMD64 渲染器无需逐句柄
分支，只按操作码翻译。此步完成即 P3 前置条件（P3 验收集，P2-b 不单独设门，随 P3 门控）。

> **风险**：char 无符号零扩展在 64 位下的 movzbq/movzbl 差异；`%ebp`→`%rbp` 栈帧偏移全部 64 位；
> 全局符号寻址 `g%d(%rip)` RIP 相对 vs 32 位绝对（P2-a 冒烟先用绝对寻址或登记局限）；.s 逐字节
> 比对仅在同目标内有意义（跨目标语义等价由 P3 行为矩阵覆盖）。

> **P2-a 完成（2026-08-26）**：g_am 全局（0=i386/1=amd64）＋64 位渲染链路全通——
> - **操作码**：irgo 的 OP_PUSHI/PUSHL/STORE/JZ/JNZ/BINOP/CMP 按 g_am 分支 64 位
>   （pushq/cmpq/addq/sqsubq/imulq/cqto+idivq/movzbq、%rax/%rcx/%rbp）。

### 5.4 P4 实施规范（ARM64 后端 —— 16B 值栈世界、AArch64 ABI 子集、qemu 闭台）

> **定位**：P4 在 i386/AMD64 双目标不动的前提下新增 **AArch64（ARM64）代码生成**。世界观与
> x86 完全不同：无标志位隐式栈机、立即数受限（12 位）、`[x29,#-imm]` 无负偏移、bl 不压栈。
> 选型约束：**值栈统一 16B 槽**（sub sp,#16 / str x0,[sp] 成对）；栈帧 x29 基址、局部槽为
> 负偏移仅能寄存器计算地址；全局布局与 AMD64 完全一致（int 8B / struct 内部 4B，数据段
> 句柄唯一差异是 `.quad` 分支已覆盖）；运行时不引 libc——AArch64 Linux 纯 syscall
> （号 read=63 / write=64 / exit=93，参数 x0–x5、号放 x8）。
>
> **P4-a 最小可行冒烟（目标：qemu 内原生运行验证渲染通路）**：
> 1. **目标标记**：boot0 增全局 `int g_ar;`（0=其他 / 1=arm64），沿用 P3 的 sed 常量折叠变体
>    （`g_ar==1`→`1==1`、`g_ar==0`→`0==1`）构建 bin_arm；irgo 主分发按 g_ar 选 irgo_arm()。
> 2. **操作码渲染 ARM64 化**：irgo_arm 九操作码——PUSHI/PUSHL/STORE 用 mov+sub sp+str，
>    BINOP 逐 token 翻译（add/sub/mul/sdiv/msub(rem)/lsl/asr/and/orr/eor/neg/cset/mvn/ldr
>    解引用/逻辑 cset），CMP 用 cmp+cset（eq/ne/lt/le/gt/ge），JZ/JNZ 用 cmp+b.eq/b.ne，
>    跳转/标签 b/L。**局部槽负偏移**必须寄存器寻址（`sub x1,x29,#-off`），不能 `[x29,#-imm]`。
> 3. **调用/栈帧**：调用序 `ldr x0,[sp]`＋`bl fN`＋`add sp,sp,#n*16`＋结果回压；参数槽
>    `16+p*16`（stp 压 16B 后原 arg0 在 x29+16）；局部槽 `0-(locn*16)`、`sub sp,sp,#16*N`；
>    pfun 序言 `stp x29,x30,[sp,#-16]!`＋`mov x29,sp`＋`sub sp,sp,#16`，尾声 `mov sp,x29;
>    ldp x29,x30,[sp],#16; ret`；p_k 返回 x0。
> 4. **最小透传**：字符串字面量 `adrp+add :lo12:strN`（.rodata 远于 ±1MB 用 adrp 不破）；
>    局部标量读写（add/sub 基址+ldr/str/strb）。其余透传句柄登记"留 P4-b"。
> 5. **运行时模板（eh() g_ar 分支）**：_start（含 gsl/gsb stdin 预载 read 63）→ bl fN →
>    print_decimal＋print_char(10)（pg_quiet 门同 amd64）→ exit 93；print_decimal/print_char/
>    print_str/print_err/print_int/exit 全部 AArch64 纯 syscall 实现（x19/x20 保值，scrtch 栈
>    .bss runt_buf 16B）。
> 6. **验收门**：bin_arm < 冒烟 → arm64.s → `aarch64-linux-gnu-as/ld`（静态，无 libc）→
>    `qemu-aarch64` 原生运行（return 42、递归 fact、print_int/print_str、局部）；i386/AMD64
>    五线全绿零变化。
>
> **P4-b 全面化（同 P2-b 模式）**：e_expr/p_a/pd/p_s 全部透传句柄 ARM64 化——局部/全局
> 1D/2D/3D 数组读写（局部跨步 16B / 全局 8B）、struct/union 成员链、`->` 链、& 取址、ecpy
> 整值拷贝、逗号/三目/switch 链、sizeof、块回收（`add sp,sp,#n*16`）、表达式语句清栈、
> 初始化器（局部/全局 .quad/.byte/.space）、数据段布局（对齐 AMD64）。tests/run_arm.sh 由
> run_amd.sh 42 例平移（bin_arm + aarch64 交叉 as/ld + qemu）。
>
> **P4-c ARM64 双目标闭台（同 P3 模式）**：bin_arm 自编 boot0_arm.pgc → selfarm.s（ARM64
> 源码态）→`aarch64-linux-gnu-as/ld`→bin1_arm（ARM64 原生静态）→ qemu 下 bin1_arm 自编 →
> selfarm2.s → bin2_arm；**门1 selfarm.s==selfarm2.s 逐字节、门2 二进制可复现、门4 三头行为
> 矩阵 5/5**（三头均在 qemu-aarch64 下原生运行）。i386/AMD64 五线零变化。
>
> > **风险**：AArch64 立即数 12 位——局部帧 >4095B 需 movz 两段（登记局限，冒烟/闭台用例
> > 帧均 <4KB）；adrp 页跨边界（as 的 :lo12: 重定位处理）；qemu 语义偏差（登记已知偏差，
> > 不作行为对照依据）；bin_arm 自编译 boot0_arm 时 IR 缓冲/数据段尺寸增长（沿用 E 系列登记）。
>
> **P4-b 完成（2026-08-26）**：透传文本 ARM64 全面化——全局/局部 1D/2D/3D 数组读写（全局
> 8B 元素、局部 16B 槽、char 稠密）、struct/union 成员链、-> 链、& 取址、ecpy、逗号/三目/
> sizeof/switch/回收/初始化器。**关键面**：① print_decimal/print_int 32 位 W 寄存器转换截断
> （镜像 amd64 movl 语义——amd64 亦 8B 装载结构体成员但打印截 32 位掩盖，ARM64 直打 64 位
> 露馅，W 截断后 42 例全部对齐）；② >65535 立即数 movz+movk 两段（PUSHI/sizeof/_start
> stdin 预读三处内联）；③ ecpy 用 [xN,#i] 寻址；④ switch 默认/收尾 b 而非 jmp。**E10**：
> pggcc4 in_buf 131072→262144（boot0.pgc 146KB）；boot0 src_buf 131072→262144、irv/irt
> 131072→262144、sts 65536→131072、stp0 1024→2048。tests/run_arm.sh **42/42**（run_amd 42
> 例平移，aarch64 交叉 as/ld + qemu 原生）；i386/AMD64 五线零变化。
>
> **P4-c 完成（2026-08-26，ARM64 双目标闭台）**：tests/boot_arm.sh——pggcc4→bin_arm（g_ar=1
> 常量折叠变体）→ bin_arm 自编 boot0_arm.pgc→selfarm.s(1759813B)→bin1_arm（aarch64 交叉
> as/ld 静态链接，无 libc）→ **qemu-aarch64 下 bin1_arm 自编**→selfarm2.s→bin2_arm；**门1
> selfarm.s==selfarm2.s 逐字节（源码态固定点）、门2 二进制可复现、门4 三头行为矩阵 5/5
> （三头均在 qemu 下原生运行）**。ARM64 自举闭台达成；i386/AMD64 六线零变化。
> **里程碑：P4（ARM64 后端）+ 双目标闭台达成**，下一步 P5：恢复 C99 特性面。

## 6. 决策记录（Q1–Q5，2026-08-26 用户拍板）

- **Q1 路线**：✅ **路线 A（多后端 + 交叉自举）**——保持无蛋红线，新增第二代码生成后端。
- **Q2 跨 binutils**：✅ **允许**引入 `aarch64-linux-gnu-as`/`-ld` 等跨 binutils（定位同 as/ld；
  落地时属基线变更，日志留痕）。
- **Q3 抽象方式**：✅ **D1b 轻量 IR**（推翻草案推荐 D1a，理由=后端解耦最大化 + 后续特性面受益）。
- **Q4 ARM64 验证工具**：✅ **允许**引入 `qemu-user`（扮演 CPU/硬件的仿真器；ARM64 闭台验证用）。
- **Q5 时序**：✅ **先移植后特性**——移植里程碑（P1–P4）排在计划特性面 P5（C99）之前。

## 7. 红线与风险评估

| 风险 | 研判 | 对策 |
|------|------|------|
| 引入新工具触碰红线 | 跨 binutils/qemu 非 C/C++ 编译器，属"工具"；但改变环境基线 | Q2/Q4 已显式放行 + 落地时日志留痕（baseline §8） |
